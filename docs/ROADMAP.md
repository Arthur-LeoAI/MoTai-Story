# 墨台产品路线图

更新时间：2026-09-12

## 当前优先范围：本地长篇 MVP

先完成本地工作台修复与生成、审校、接受正文、确认事实闭环，再由作者配置 DeepSeek/OpenAI Key 并明确开始真实测试。验收目标是约 20 章、5 万字，检查人物、事件、时间线和伏笔的一致性；模拟测试通过不代表此目标已经验证。

账号、服务器托管和外部数据库暂缓。当前保留 ownerId、schemaVersion、服务端章节版本校验和存储事务边界，后续迁移时仍需要权限设计、数据迁移及回归验收。下列旧版路线图作为后续候选，不代表当前新版界面已具备全部旧功能。

本文是墨台后续升级的共同目标清单。它约束版本范围，避免每次只追加零散功能；完成一个里程碑前，优先修复该里程碑的缺口，而不是把未验证的新功能塞进发布包。

## 当前版本：v1.1.0

定位：本地优先的 Windows 中文小说创作工作台。

本版已交付：作品与章节管理、设定库、人物关系与时间线、AI 写作与图片能力、封面历史、章节插图、五种导出、自动备份恢复、四套主题/壁纸、桌面 EXE、GitHub 自动检查与发布流程。

发布验收：`npm run check`、Playwright 关键流程和 Windows 安装包构建通过；GitHub Release 含安装包、SHA-256、更新日志；不包含正文、封面、备份或 API Key。

## 下一版本：v1.1.1 稳定性修订

目标：消除真实作者使用中会打断写作的错误，不新增大功能。

- AI 请求状态、401/403/429、网络超时、模型路径错误必须给出中文原因和可执行下一步。
- 设定库、人物关系、章节规划在切换作品、刷新和重启后不能串书或丢失。
- 四套主题下的弹窗、菜单、表单、导出面板和空状态必须可读。
- 桌面版升级、启动、退出与本地数据迁移完成一轮人工冒烟检查。

验收：新增回归测试覆盖每一个修复；24 项以上 Node 测试与全部 Playwright 流程通过；不改变用户小说数据格式。

## v1.2.0：长篇写作控制台

目标：让“设定 -> 卷纲 -> 章纲 -> 正文”的推进更可控。

- 分卷管理：每卷有目标、核心矛盾、阶段高潮和收束条件。
- 人物成长弧与伏笔回收表：可标注引入章节、推进章节、回收章节和当前状态。
- 章节卡增强：拖拽排序、场景、人物、冲突、爽点、钩子和字数目标。
- AI 写作预设：续写、战斗、对话、情感、过渡五种模式；可显示将使用的上下文摘要与预计输出字数。

验收：新建一部作品后，作者无需阅读开发文档即可完成一卷规划、三张角色卡、六章章节卡，并让 AI 按当前章纲生成正文。

## v1.3.0：作品包与团队协作

目标：让伙伴安全地共同开发项目代码或交换单部小说，不把私有数据库放入 Git。

- 单本 `.motai-work.json` 导出与导入，包含该作品、章节、设定与可选封面，不包含 API Key。
- 导入预览、冲突提示和自动回退备份，避免覆盖本地作品。
- 协作说明页：从 GitHub 分支、Pull Request 到作品包交换的明确流程。
- 作品归档、搜索、标签筛选和最近修改记录。

验收：两台电脑可安全交换一部小说；导入失败不会损坏现有作品；协作者不需要接触 `data/db.json`。

## v2.0.0：可选云同步与多人协作

前置条件：v1.x 的本地数据、备份恢复、作品包和发布流程持续稳定。

探索范围：账号、端到端隐私说明、云端作品版本历史、协作者权限、段落级冲突处理。该版本不在未完成数据安全设计前启动开发。

## 每次升级的完成定义

1. 先在本文选择一个明确版本目标，并把不属于该目标的想法放入后续版本。
2. 实现时同步更新 README、架构文档、交接文档和 `CHANGELOG.md`。
3. 不提交 `.env.local`、`data/db.json`、封面、备份、日志或本机安装产物。
4. 运行 `npm run check` 与 `npm run test:e2e`；涉及桌面端时再验证安装包启动、保存和退出。
5. 合并到 `main` 后创建 `vX.Y.Z` 标签，由 GitHub Actions 构建安装包、SHA-256 和 Release。
6. 发布后记录真实使用中发现的问题，并优先归入最近的稳定性修订版本。
